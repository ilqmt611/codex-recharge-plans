## 先搞清楚：你充值的到底是什么

Codex 这个工具本身免费。CLI、桌面 App、IDE 扩展、网页端，下载安装都不要钱，真正计费的是背后的模型算力。你让它读文件、改代码、跑长任务，每一步都按 token 计量——token 可以理解成模型的“计价字数”，输入和输出分开算，输出通常更贵。

这里有个反直觉的点：花钱多少跟“问了几条消息”关系不大，跟“每条消息塞进去多少上下文”关系极大。让它读一个 2000 行的文件，整个文件都变成输入 token；一个对话从早聊到晚，前面几十条消息每次都会重发一遍。记住这一点，后面省额度的方法你基本能自己推出来。

## 充值之后：额度怎么算，还剩多少怎么看

Codex 的限额不是“每天清零”，官方按 5 小时滚动窗口计量，本地消息和云端任务共享同一个窗口，可能另有每周上限。这就是为什么有人一天没发几条消息就撞了顶——每条消息的“重量”差别很大。

看剩余额度的方法：CLI 里敲 `/status`，能看到当前模型、审批策略、剩余上下文和限额情况；想看跨设备的完整用量，去 ChatGPT 网页版的 Codex 用量面板（Settings 里的 Usage）。API key 用户则在 OpenAI Platform 后台看账单。

两个实用建议。一是跑完一个小任务后再敲一次 `/status`，对比上下文用量涨了多少，建立“一次对话大概花多少”的基准，之后哪次异常烧额度一眼能看出来。二是撞顶了先买积分续命，别急着升档——升档是下策，学会省才是上策。

## 让额度更耐用的五个习惯

这套习惯来自官方定价文档里“怎么让限额更耐用”一节，按立竿见影的程度排：

1. **指令写具体。**“帮我改进下这个项目”会让它满项目翻文件猜你想干嘛；“改 src/auth.ts 里的 login 函数，加输入校验”直接到位。大部分浪费发生在模型瞎读文件上。
2. **AGENTS.md 瘦身。** 这份项目说明书每条消息都会被塞进上下文。大项目按子目录分层放小的，别在根目录堆几百行巨无霸。
3. **MCP server 按需开。** 每接一个外部工具，它的描述都会占掉你每条消息的上下文，用得着才开，用完就关。
4. **常规任务切小模型。** 用 `/model` 切到 GPT-5.4 或 GPT-5.4-mini，同档限额能翻好几倍，改代码、调小 bug 完全够，硬骨头再上最强的。
5. **切活用 `/new`。** 在 CLI 里开新对话重置上下文，别一个会话从早聊到晚，下午每条消息都在重发上午那堆早就没用的内容。

贴在显示器边上的版本就一句话：上下文越小，额度越耐用。

国内号码不在 OpenAI 支持范围，这是它的反滥用机制。只在网页用 ChatGPT 的话，Google 账号加两步验证通常就够；要用 Codex 桌面端，一般得准备一张海外手机号，比如英国的 giffgaff 卡（注意按运营商规则定期保号）。

**充值成功后还显示普通会员？**
先刷新页面、退出重新登录，确认看的是下单那个邮箱的账号，等 5–10 分钟再看，多数情况是缓存没刷新。超过半小时还没到账，去平台的订单页提交工单。

多数代充渠道要求账号当前没有在期订阅，也不支持中途补差价升级。等订阅到期、账号变回普通状态后再下单。这类月付套餐一般不自动续费，到期后重新下单一次就行。
